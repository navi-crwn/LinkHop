LinkHop сокращает ссылки, считает клики и делает QR-код для каждой ссылки. Это сервис коротких ссылок семейства HOP, он работает на [link.hel.ink](https://link.hel.ink). Короткие ссылки открываются по адресу `hel.ink/l/slug`.

Сократить ссылку может любой человек без аккаунта. Бесплатный HOP ID сохраняет ваши ссылки и показывает их статистику. HOP ID — это единый аккаунт для всех приложений HOP, он живёт в [хабе](https://github.com/navi-crwn/HEL.ink) на `hel.ink` и `hub.hel.ink`. У LinkHop нет собственных страниц входа, регистрации и профиля: вход выполняет хаб и возвращает вас с короткоживущим билетом, а приложения используют одну общую базу данных.

## Семейство HOP

| Приложение | Адрес | Репозиторий | Что делает |

| **BioHop** | [bio.hel.ink](https://bio.hel.ink) · `hel.ink/b/…` | [navi-crwn/BioHop](https://github.com/navi-crwn/BioHop) | Одна страница link-in-bio для всего, чем вы занимаетесь. |
| **PixelHop** | [pixel.hel.ink](https://pixel.hel.ink) · `p.hel.ink/…` | [navi-crwn/PixelHop](https://github.com/navi-crwn/PixelHop) | Хостинг изображений с альбомами и прямыми ссылками. |

## Возможности

- Короткие ссылки со случайным или собственным слагом (от 3 до 255 символов), необязательным паролем, сроком действия и QR-кодом в PNG, SVG или JPG.
- Ограничения ссылки: время начала, максимальное число кликов, запасной адрес на случай, когда срок истёк или клики закончились, и тип редиректа 301, 302, 307 или 308.
- Маршрутизация: до 20 правил, которые направляют посетителей на другой адрес по стране, языку, устройству, операционной системе или браузеру, и A/B-разделение между 2–5 адресами с весами. Конструктор меток кампаний (UTM) заполняет параметры `utm_*`.
- Открытие в приложении: на iOS и Android ссылка может сначала попробовать установленное приложение, а запасным вариантом будет App Store или Google Play.
- Статистика: клики, уникальные посетители, страны и города, устройства, браузеры, встроенные браузеры приложений, источники переходов, а также сканирования QR-кода в сравнении с прямыми кликами. Выбранный период сравнивается с предыдущим. Журналы отдельных кликов хранятся 30 дней.
- Порядок: папки, теги, поиск, массовые действия, комментарии к ссылке, импорт CSV до 500 строк и палитра команд по Ctrl или Cmd + K. В настройках есть экспорт ссылок со статистикой в CSV.
- Проверка ссылки на `/check`: вставьте ссылку `hel.ink`, чтобы увидеть, куда она ведёт, прежде чем её открыть. Ничего не нажимается и не учитывается.
- Мониторинг адресов назначения: раз в сутки LinkHop спрашивает у каждого действующего адреса, отвечает ли он ещё, и после трёх неудачных проверок подряд отправляет владельцу письмо. Это можно отключить в настройках.
- Предупреждение о содержимом: ссылку можно пометить как чувствительную или только для взрослых, и посетитель увидит уведомление, прежде чем продолжить.
- Защита от злоупотреблений: ограничения частоты и квоты, чёрный список доменов, блокировка IP, проверка посетителей на прокси и VPN, форма жалобы и ежечасное сканирование на фишинг, мошенничество и другие вредные ссылки, с необязательными запросами к Google Safe Browsing и URLhaus.
- API и вебхуки: REST API с токенами по областям доступа и ключами идемпотентности, подписанные вебхуки для пяти событий ссылок и конфигурация ShareX.
- Девять языков: English, 简体中文, Deutsch, Bahasa Indonesia, 日本語, Português (Brasil), Español, Français и Русский. Добавьте `?lang=ru` к адресу любой страницы, чтобы переключить язык; выбор запоминается в cookie.
- Приватность: без рекламы, без сторонних трекеров и без скриптов, шрифтов и изображений с CDN. Библиотеки входят в сборку или лежат в `public/vendor`. Остаются два сторонних хоста: Cloudflare Turnstile в гостевой форме и плитки OpenStreetMap под картой в статистике.
- Самостоятельное размещение: установка одной командой, скрипты обновления и удаления, ночные резервные копии и подписанный административный API для центра управления HOP.

Страницы bio (`hel.ink/b/вы`) создаются в [BioHop](https://github.com/navi-crwn/BioHop), а не в LinkHop. Единственный случай, когда LinkHop всё ещё отдаёт их сам, описан в разделе [Страницы bio](#страницы-bio).

## Что где находится

| Что | URL |
| --- | --- |
| Короткая ссылка | `hel.ink/l/slug` |
| Старая форма короткой ссылки | `hel.ink/slug`, перенаправляет на `hel.ink/l/slug` до 27 ноября 2026 года (`LEGACY_SLUG_UNTIL`) |
| Страница bio (BioHop) | `hel.ink/b/name` |
| Панель и API | `link.hel.ink`, вход через хаб на `hub.hel.ink` |
| Ваш аккаунт | `hub.hel.ink`: профиль, пароль, двухфакторная аутентификация, токены API, скачивание данных, удаление аккаунта |

28 октября 2026 года короткие ссылки переехали с `hel.ink/slug` на `hel.ink/l/slug`, чтобы на `hel.ink` могли жить несколько приложений HOP. Ничего не удалялось. Панель, QR-коды, API и экспорт аккаунта показывают новую форму. На вашей собственной установке публичный хост задаётся в `PUBLIC_URL` (по умолчанию равен `APP_URL`), а `php artisan links:announce-migration` отправляет каждому владельцу ссылок письмо с его ссылками в новой форме (`--reminder` отправляет второе письмо).

## Установка

Установщик проверяет ваш компьютер, задаёт несколько вопросов и может развернуть хаб HOP ID рядом с LinkHop:

```bash
curl -fsSL https://raw.githubusercontent.com/navi-crwn/LinkHop/main/install.sh | bash
```

Из клона репозитория запускайте `./install.sh`. Для обновления — `./update.sh`, для удаления LinkHop — `./uninstall.sh`. Флаг `--yes` принимает все значения по умолчанию, `--dry-run` показывает шаги, не выполняя их, а `--help` перечисляет остальные параметры.

- Для `install.sh` нужны PHP 8.2 или новее (он использует `php8.3`, если тот установлен; другой можно выбрать через `PHP_BIN`), Composer, Node.js 20 или новее и база данных: SQLite или MySQL/MariaDB. Он записывает закрытый `.env` и `start.sh`, который запускает веб-сервер, обработчик очереди и планировщик.
- `update.sh` сначала копирует базу данных в `backups/` (SQLite или MySQL/MariaDB), переводит сайт в режим обслуживания, забирает новый код, пересобирает, выполняет миграции и возвращает прежнюю версию, если какой-то шаг до миграций завершился ошибкой. Если копию базы сделать не удаётся, он останавливается; с `--no-backup` он продолжает без копии.
- `uninstall.sh` удаляет установленные пакеты и собранные файлы, а ваши `.env`, базу данных, загрузки и журналы оставляет. С `--purge` удаляется и это, а перед этим нужно ввести название сайта.

> [!NOTE]
> LinkHop хранит аккаунты в хабе HOP ID ([HEL.ink](https://github.com/navi-crwn/HEL.ink)); режима без хаба нет. Установщик может развернуть хаб рядом с LinkHop (по умолчанию, около минуты) или подключиться к хабу, который у вас уже работает. Чтобы установить хаб и несколько приложений сразу, используйте `install-family.sh` из репозитория HEL.ink.

### Ручная установка

Нужны PHP 8.2 или новее с обычными расширениями Laravel и `gd` или `imagick` (QR-коды в PNG), Composer, Node.js 20.19 или новее и база данных. [Хаб](https://github.com/navi-crwn/HEL.ink) должен работать с той же базой: ему принадлежат таблицы аккаунтов (`users`, `api_tokens` и другие), и именно он выполняет вход.

```bash
# Общие пакеты hop/auth, hop/ui и hop/safety подтягиваются из GitHub через Composer.
git clone https://github.com/navi-crwn/LinkHop.git
cd LinkHop
composer install --no-dev --optimize-autoloader
npm ci && npm run build

cp .env.example .env
php artisan key:generate          # затем отредактируйте .env, см. ниже
php artisan migrate --force       # только таблицы этого приложения
php artisan storage:link
php artisan serve --port=8001
```

Для локальной работы задайте `APP_ENV=local`, `APP_URL=http://localhost:8001`, `PUBLIC_URL=http://localhost:8001`, `HOP_HUB_URL=http://localhost:8000` (хаб, запущенный через `php artisan serve`) и `SESSION_SECURE_COOKIE=false`, а в хабе — `LINKHOP_URL=http://localhost:8001`. Гость, открывший LinkHop, попадает на страницу входа хаба и возвращается уже авторизованным.

В продакшене должны постоянно работать две вещи: обработчик очереди (`php artisan queue:work --tries=3`) и планировщик (строка cron `* * * * * cd /путь/к/linkhop && php artisan schedule:run`). Планировщик запускает сканирование на злоупотребления, мониторинг адресов назначения, повторы вебхуков, очистку данных по правилам приватности, удаление гостевых ссылок и резервное копирование.

**Кому принадлежит база данных.** Каждое приложение HOP выполняет в общей базе только свои миграции. Миграции LinkHop лежат в `database/migrations`. История таблиц аккаунтов хранится в `database/migrations-archive` и больше не выполняется; тесты строят схему из неё. Не запускайте `migrate:fresh` на базе, которой пользуется хаб.

**Местоположение посетителей.** Страна и город берутся из локальной базы DB-IP Lite, которую `geolite:update` обновляет раз в неделю. Если для публичного адреса в ней нет ответа, LinkHop обращается не более чем к двум веб-сервисам: freeipapi.com, ip-api.com, ipapi.co, ipinfo.io или abstractapi.com. Адрес посетителя сохраняется только в виде хеша с ключом.

**Резервные копии.** Планировщик запускает `backup:run` каждый день в 02:45. В архив входят база данных, `storage/app/public` и `.env`, а записывается он на диски из `BACKUP_DISKS`. Для резервной копии MySQL или MariaDB на сервере нужен `mysqldump`. В `.env` лежат ваши секреты, поэтому защитите диск с копиями или задайте `BACKUP_ARCHIVE_PASSWORD`.

**За Cloudflare.** LinkHop отправляет политику безопасности содержимого (CSP), которая доверяет только скриптам с nonce страницы. Email Address Obfuscation (Scrape Shield) и Rocket Loader (Speed, Optimization) от Cloudflare вставляют собственные скрипты без этого nonce, поэтому браузеры их блокируют, а блокировки попадают в `storage/logs/csp-*.log`. Отключите обе функции в панели Cloudflare. LinkHop они не нужны. Добавление их в политику не сработает при политике с nonce, потому что `'strict-dynamic'` игнорирует списки разрешённых хостов.

**Один хост.** В размещённом сервисе LinkHop разделён на две части: панель на `link.hel.ink` и короткие ссылки на `hel.ink/l/`. Правила nginx для такого разделения лежат в репозитории хаба, в `deploy/nginx/`. Если хост один, задайте `APP_URL` и `PUBLIC_URL` одним и тем же значением.

## Использование

**Сократить ссылку.** Вставьте длинный адрес, при желании выберите слаг, пароль или срок действия, нажмите Shorten и скопируйте результат. Гостевые параметры лежат в разделе Advanced на главной странице; после входа в New link доступны все перечисленные выше параметры.

**Страницы bio.** Войдите на [bio.hel.ink](https://bio.hel.ink) с тем же HOP ID, выберите имя и делитесь адресом `hel.ink/b/вашеимя`.

## API

Токены API создаются в хабе (HOP ID, Settings, API) и работают во всех приложениях HOP. LinkHop читает их из общей таблицы `api_tokens`. У токена есть области доступа (scopes): `link:create`, `link:read` и `link:delete`. Токен, созданный до появления областей, их не имеет и может всё. API отвечает на `link.hel.ink/api`, а также на `hel.ink/api`, который до 27 ноября 2026 года перенаправляет туда. Ограничение частоты задано для каждого токена: 100 запросов в час, если токен не задаёт своё.

Создание короткой ссылки (`link:create`). BioHop делает этот вызов, когда блоку bio нужна короткая ссылка.

```bash
curl -X POST https://link.hel.ink/api/shorten \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://example.com", "alias": "my-link"}'
```

| Поле | | |
| --- | --- | --- |
| `url` | обязательное | Полный адрес с `http://` или `https://`, до 2048 символов. Отклоняется, если проверка безопасности его помечает. |
| `alias` | необязательное | Слаг: от 3 до 255 символов из `A-Z a-z 0-9 _ -`. Зарезервированные слова и занятые слаги отклоняются. Если не указан, будет случайным. |
| `folder` | необязательное | Название папки в аккаунте. Если её нет, она создаётся. |
| `password` | необязательное | От 4 до 50 символов; посетителю придётся его ввести. |
| `expires_at` | необязательное | Дата и время в формате ISO в будущем. |
| `starts_at` | необязательное | Дата и время, до которых посетители видят «Not live yet». |
| `max_clicks` | необязательное | После этого числа кликов ссылка перестаёт работать (от 1 до 10 000 000). |
| `fallback_url` | необязательное | Куда попадают посетители после окончания срока или лимита кликов. Не может быть другой короткой ссылкой. |
| `redirect_type` | необязательное | `301`, `302` (по умолчанию), `307` или `308`. |
| `content_warning`, `warning_reason` | необязательное | `none`, `sensitive` или `adult`, и примечание до 255 символов, которое видят посетители. |
| `routing_rules`, `ab_variants`, `app_links` | необязательное | Маршрутизация по посетителю, A/B-разделение и глубокие ссылки. Форматы описаны на странице API docs в панели. |

```json
HTTP 201
{"success": true,
 "data": {"url": "https://hel.ink/l/my-link", "slug": "my-link", "target_url": "https://example.com",
          "status": "active", "content_warning": "none", "warning_reason": null,
          "created_at": "2026-11-02T10:00:00+00:00", "expires_at": null, "starts_at": null,
          "max_clicks": null, "fallback_url": null, "routing_rules": [], "ab_variants": [],
          "app_links": null, "redirect_type": "302"},
 "message": "Link created successfully"}
```

Ошибки всегда имеют один вид: `{"success": false, "error": "…", "message": "…"}`. `401` означает неизвестный или просроченный токен, `403` — нехватку области доступа либо заблокированный или неподтверждённый аккаунт, `422` — ошибку проверки данных (в `messages` перечислены поля), `429` — исчерпанную квоту или ограничение частоты.

Чтобы безопасно повторять запрос, передавайте в `POST /api/shorten` заголовок `Idempotency-Key`. Тот же ключ с тем же телом возвращает первый ответ (`Idempotent-Replayed: true`) и ничего не создаёт повторно. Тот же ключ с другим телом даёт `422`. Ключи хранятся 24 часа.

Прочитать ссылку (`link:read`) можно через `GET /api/links/{slug}`: в ответе те же `data` плюс `clicks`. Удалить (`link:delete`) — через `DELETE /api/links/{slug}`. Оба запроса отвечают `404` для слага, которого нет в аккаунте токена.

Вебхуки настраиваются в настройках: до пяти адресов https, каждый вызывается при `link.created`, `link.updated`, `link.deleted`, `link.limit_reached` и `link.expired`. В сообщении есть заголовок `X-LinkHop-Signature` — HMAC-SHA256 от метки времени и тела. Неудавшаяся доставка повторяется через 1 минуту, 5 минут, 30 минут и 2 часа, а вебхук, у которого десять доставок подряд завершились неудачей, отключается.

Конфигурацию ShareX можно скачать на странице API docs в панели.

## FAQ

**Это бесплатно?** Да. Платного тарифа и закрытых функций нет.

**Нужен ли аккаунт?** Нет. Сократить ссылку может любой без аккаунта. Гостевые ссылки удаляются через 14 дней без кликов и в любом случае через 30 дней. Бесплатный HOP ID сохраняет ваши ссылки, показывает их статистику и пускает вас в остальные приложения HOP.

**Где моя страница bio?** В BioHop, по адресу `hel.ink/b/` и выбранному вами имени. Редактировать её можно на [bio.hel.ink](https://bio.hel.ink).

**Что записывается при клике?** Время, страна и город, устройство, браузер и источник перехода, а также хеш с ключом от адреса и браузера, который меняется каждый день и нужен для подсчёта уникальных посетителей. Сам адрес не сохраняется, а журналы кликов удаляются через 30 дней.

**Как пожаловаться на плохую ссылку?** Воспользуйтесь формой жалобы на `/report-abuse`. Жалобы попадают в очередь злоупотреблений центра управления HOP рядом с находками автоматического сканирования.

**Можно ли использовать свой домен?** Да, если разместить собственную копию рядом с хабом. `APP_URL` — хост панели, `PUBLIC_URL` — хост коротких ссылок, `HOP_HUB_URL` — хаб.

### Страницы bio

На hel.ink страницы bio принадлежат BioHop. Установка на одном сервере без BioHop по-прежнему может отдавать их из встроенного пакета `hop/bio` (`packages/bio`), если задать `BIO_ENABLED=true`. Когда рядом есть BioHop, оставьте `false`: тогда пакет не регистрирует маршруты и не требует таблиц. `php artisan db:seed --class=ExampleBioSeeder` создаёт на установке для разработки пример страницы bio и несколько примеров коротких ссылок.

## Участие в разработке

1. Сделайте форк репозитория и создайте ветку.
2. Внесите изменение и запустите `vendor/bin/pint` и `php artisan test`.
3. Отправьте ветку и откройте pull request в `main`.

Для нового поведения добавляйте тесты. О проблемах безопасности сообщайте приватно, как описано в [SECURITY.md](SECURITY.md), а для всего остального используйте шаблоны issue.
